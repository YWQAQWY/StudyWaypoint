# StudyWaypoint

StudyWaypoint 是适用于 Ubuntu/Debian 与 Windows x64 的学习计划与进度追踪器。它把课程安排成日历和每日任务，记录学习计时、阅读与练习步骤、证据、验收结果及复盘。你可以导入符合 v3 格式的 JSON 计划，多个计划的进度分别保存在本机；也可以配置自己的 API，在应用中与 AI 讨论并生成计划草稿。

公开发行版只内置**通用一周示例计划**，不包含开发者或任何用户的私人课程、学习记录和数据库。应用不会替你完成实验，也不会执行证据中填写的代码或文件路径。

## 功能一览

- **课程日历**：按起始日期展示完整计划，查看每周主题、每日任务和计划时长。
- **每日学习**：查看阅读材料、编码练习、交付物、验收项及每周 LeetCode 题目；勾选已完成的步骤并写笔记、复盘。
- **时间记录**：开始、暂停学习计时，或补录线下学习分钟；按理论、实践、验收分配每日时间预算。
- **证据与验收**：登记产物路径、链接、提交 hash、测试日志等证据，关联到验收项并人工判定结果。
- **计划库与备份**：预览、导入、更新、切换计划；分别导出和恢复每个计划的数据。
- **桌面工作区**：可折叠左侧导航、浅色/深色/跟随系统主题、可拖动 AI 双栏、键盘操作和减少动态效果支持。
- **AI 规划**：使用 OpenAI 兼容的 Chat Completions API 讨论学习目标；默认通过自备 SearXNG 联网检索，主动启用时优先使用 Brave。对话中的结构化草稿在侧栏持续更新，确认后自动生成、校验并导入 v3 计划。

## 安装与启动

### 系统要求

- Ubuntu/Debian 图形桌面：Python 3.11 或更新版本、GTK 3、WebKitGTK 4.1；安装 `.deb` 时，`apt` 会处理系统软件包依赖。
- Windows 10/11 x64：使用独立的便携 ZIP，内含 Python 运行时；以 Edge 应用窗口或默认浏览器显示界面，不需要 GTK。尚无 Windows 安装程序或 macOS 发行包。
- 学习记录保存在本机；打开课程中的外部网页需要网络。

### 安装发行版

下载 `studywaypoint_1.4.0_all.deb`，在该文件所在目录运行：

```bash
sudo apt install ./studywaypoint_1.4.0_all.deb
```

安装后从应用菜单搜索 **StudyWaypoint**，或在终端运行 `studywaypoint`。如果同时下载了 `SHA256SUMS`，可先在发行文件目录执行 `sha256sum -c SHA256SUMS` 核对下载文件。

### Windows x64 便携包

下载 `StudyWaypoint-1.4.0-windows-x64.zip`，完整解压，双击其中的 `Start StudyWaypoint.cmd`。程序会启动本地服务并打开 Edge 应用窗口；没有 Edge 时改用默认浏览器。学习数据保存在 `%LOCALAPPDATA%\StudyWaypoint\`，与解压目录分离。包内只含通用示例计划，不含私人数据或 API Key。完整的启动、升级、备份和故障处理说明见 [Windows 使用指南](WINDOWS_GUIDE.md)。

发布者可用 `python3 packaging/build_windows.py` 生成 Windows ZIP 及其 `.sha256` 校验文件；构建时从 Python.org 和 PyPI 下载固定版本、校验 SHA-256 后打包，不需要在 Linux 构建机安装 Windows Python。Windows 真机启动与 Edge 窗口交互仍需在 Windows 上验收。

### 从源码运行或安装到当前用户

解压源码包，进入含 `README.md` 的项目目录：

```bash
./run-desktop.sh
```

如果没有管理员权限，但系统依赖已安装，可将应用安装到当前用户：

```bash
python3 packaging/install_user.py
~/.local/bin/studywaypoint
```

用户安装的位置为 `~/.local/opt/StudyWaypoint/`，同时创建应用菜单项。只需要浏览器界面时，运行 `python3 server.py`，再打开 <http://127.0.0.1:8765>；可用环境变量 `TRACKER_PORT` 更改端口。浏览器服务默认仅监听本机。

### 桌面界面与快捷操作

左侧菜单可收起为仅图标模式，状态会在重启后恢复。顶部的主题按钮可快速切换明暗模式；“设置与备份”中的“外观”还可选择跟随系统。AI 规划页可拖动聊天区与计划区之间的分隔线，也可用分隔线上的左右方向键调整宽度；右侧确认按钮始终位于计划栏底部。聊天输入按 `Ctrl+Enter`（macOS 键盘为 `⌘+Enter`）发送。界面遵守系统的“减少动态效果”偏好。布局偏好保存在本机数据目录的 `ui_preferences.json`，即使桌面服务重启后端口改变也可恢复；它不包含课程、对话或密钥。完整布局见 [当前 UI 文本说明](CURRENT_UI.txt)。

## 第一次使用

1. 打开应用。可以先浏览内置的一周示例，也可以按下文导入自己的计划。
2. 在“今天”设置**学习起始日期**与**时区**。起始日期对应计划的 `W01D01`；“课程日历”会据此显示后续日期。
3. 打开当天任务，阅读课程资料，亲自完成练习与交付物。阅读、练习的勾选表示已操作，不等于自动通过验收。
4. 学习时开始计时，结束时暂停或结束。线下学习可以补录分钟；运行中的计时会持久化，重新打开应用仍可查看。
5. 在“添加证据”中记录实际产物的路径、链接、提交 hash 或测试结果，再把证据关联到对应验收项，按实际情况标记“通过”或“未通过”。要求证据的验收项必须先关联证据才能通过。
6. 需要时更新任务状态、笔记、每日复盘和时间预算。时间预算的修改会留下历史记录。

证据是**文字引用记录**，不是上传文件本体。填写文件路径不会把该文件复制到应用，也不会运行、检查或修改实验代码。

## AI 规划：从对话生成计划

1. 在“设置与备份”填写自己订阅的 **OpenAI 兼容 API** 的 HTTPS 基础地址、API Key 和模型名称，保存后启用对话。应用向基础地址追加 `/chat/completions`。`https://api.deepseek.com` 与 `deepseek-v4-pro` 只是默认示例；使用其他兼容服务时改成该服务提供的基础地址（如末尾带 `/v1`）和模型名。推理强度默认“高”；若服务商不接受 `reasoning_effort` 参数，改选“服务商默认”。
2. 告诉 AI 你的基础、目标、可投入时长、希望完成的项目与验收方式。首次规划回复前，应用会请求结构化草稿更新；侧栏可先展示部分计划和待确认问题。继续自然语言反馈，例如“删掉 Python 基础，第三阶段增加项目”；未修改的阶段和任务会保留稳定 ID。
3. 如需**联网检索**，先配置并测试自己的 SearXNG 实例。默认只通过 SearXNG 搜索；也可主动启用 Brave Search API，成功时优先使用 Brave，失败时回退 SearXNG。普通对话可不联网；讨论完整路线或具体资源时，模型可在当前对话中调用搜索工具。不支持工具调用的模型会按明确的规划或资源需求执行有限检索。也可点击“联网检索系统课程”。界面显示搜索状态、来源和核实状态。
4. 检查侧栏中的名称、目标、周期、时长、阶段、任务、资源及待确认问题。周期或时长未确定时继续对话；每周总时长会确定性地分配到七天。模型提交的是局部草稿补丁，应用校验版本并持久化，刷新页面仍可恢复。搜索结果会在返回后补充到草稿；侧栏显示的资源必须来自检索证据。
5. 确认草稿已符合意图后，点击侧栏底部的**“确认计划并导入”**。如果计划 ID 已存在，须先勾选更新现有计划。应用冻结当前修订，按已确认阶段生成既有 v3 JSON，检查所有链接来源，最多修正两次，再用原有校验器验证并自动调用原计划导入器。完成后点“查看导入的计划”进入日历；整个流程无需手动下载或上传 JSON。失败时保留草稿和聊天，可重试同一次确认。原有手动生成入口仍在折叠的“旧版手动生成草稿”区域。

内部草稿保存在本机 `ai_plan_draft.json`，与最终课程 JSON 分离，包含修订号与确认快照；不会混入导入文件或学习备份。搜索状态和草稿状态分别更新，侧栏可在检索尚未完成时预览草稿。兼容模型的普通对话和工具调用可增量显示回复，模型拒绝流式请求时回退普通回复；侧栏通过本机状态轮询更新。

### Brave Search：申请并填写 Key

1. 在 [Brave Search API 控制台](https://api-dashboard.search.brave.com/) 注册或登录，按控制台提示开通 Search 计划并创建 API Key。该 Key 属于搜索服务，和模型 API Key 不同；以控制台显示的额度和费用为准。
2. 在应用“设置与备份”中勾选**启用第三方搜索**，把 Key 填入“Brave Search API Key”，点击“保存配置”，再点“测试 Brave”。已有 Key 留空会保留原值；关闭开关不会删除 Key。
3. 启用并保存后，新的联网检索优先访问 Brave；故障时明确提示并尝试回退到已配置的 SearXNG。Brave 请求通过 `X-Subscription-Token` 认证。[Brave 官方快速入门](https://api-dashboard.search.brave.com/documentation/quickstart)

### SearXNG：不用 Brave Key

1. 按 [SearXNG 官方容器安装指南](https://docs.searxng.org/admin/installation-docker)运行自己的实例，或使用你信任的现有实例。在实例的 `settings.yml` 中启用 JSON 输出：

   ```yaml
   search:
     formats:
       - html
       - json
   ```

2. 用 `curl 'http://127.0.0.1:8888/search?q=python&format=json'` 确认返回含 `results` 的 JSON。端口按你的实例实际端口修改；若返回 403，检查 JSON 格式是否已启用。许多公共实例禁用 JSON 接口，优先使用自己的实例。[SearXNG 搜索接口](https://docs.searxng.org/dev/search_api.html)
3. 在应用“设置与备份”中填写实例根地址，例如 `http://127.0.0.1:8888`，保存后点“测试 SearXNG”。本机地址可使用 HTTP，远程地址必须是 HTTPS。默认模式不需要 Brave Key，但实例必须自行部署并持续运行。发行包不自带 SearXNG，也不会硬编码公共实例；未配置或不可达时会显示失败原因，普通模型对话仍可使用。

模型服务商以及你选择的检索服务可能消耗各自的 API 配额或资源。对话内容会发送给模型服务商，搜索词会发送给实际使用的检索来源；SearXNG 还会请求其上游搜索源。密钥、对话、检索证据、内部规划草稿与最终 JSON 草稿保存在本机数据目录的独立文件中，权限为仅当前用户可读写；它们不会包含在学习备份或公开发行包内。可在界面中单独删除密钥、清空对话。`search_result_only` 只说明搜索提供者返回过该链接；`content_verified` 表示应用成功读取了网页正文，不代表课程质量已人工认证。确认前请核对课程、视频章节与网址。现有 v3 格式要求**每周至少两条 LeetCode 题目链接**以及每天至少一条阅读资源；没有可追溯链接时生成会明确失败，不会编造。应用不会替你完成课程实验。

模型接口参考：[DeepSeek 的 OpenAI 兼容 Chat Completions 示例](https://api-docs.deepseek.com/api/create-chat-completion/)。DeepSeek API 的内置 `web_search` 工具目前会被忽略，因此使用它时仍需配置一个外部检索来源。[DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)

## 导入自己的计划

1. 在“设置与备份”→“计划库”选择本机的 **UTF-8 `.json` 文件**。桌面窗口标题栏的“导入 v3 JSON 计划”按钮也可使用。
2. 阅读导入预览：应用会校验格式，并显示计划名称、周数、天数、总小时数，以及新增、变更、未变、移除的学习日。
3. 确认后导入并切换到该计划。格式错误会显示校验信息，不会导入。正在计时时，请先结束计时，再导入或切换计划。
4. 在计划库中可以随时切回其他已导入计划。不同 `plan_id` 的数据库彼此独立。

可从计划库点击“下载示例计划”，或复制仓库内完整可用的 [示例 v3 JSON](examples/sample_plan_v3.json) 开始修改。**导入自己的新计划时，先改成新的 `plan_id`**，再修改名称、课程内容和时间安排；否则相同 ID 会被视为已有计划的更新。

### v3 JSON 顶层格式

JSON 根节点必须是对象。以下字段构成可导入计划的主要结构；完整字段和嵌套对象请以示例文件为模板。

| 字段 | 格式和要求 |
| --- | --- |
| `schema_version` | 以 `3.` 开头的字符串，例如 `"3.0"`。 |
| `plan_id` | 唯一且稳定的 ID，3–80 个字符；首字符为英文字母或数字，其余可用英文字母、数字、`.`、`_`、`-`。建议不要随内容版本改变。 |
| `plan_name` | 计划的显示名称，建议填写清楚。 |
| `curriculum_version` | 非空的内容版本字符串，例如 `"1.0.0"`。 |
| `weeks` | 1–52 的整数。 |
| `days_per_week` | 固定为 `7`。 |
| `daily_hours` | 7 个数字，依次对应每周第 1–7 天；这个七天时长模式会重复用于每一周。每项至多 24 小时，并需与每天的 `planned_minutes` 对应。 |
| `total_planned_hours` | 全部 `days[].planned_minutes` 之和除以 60，单位小时。 |
| `weekly_themes` | 非空字符串数组，恰好每周一个主题。 |
| `leetcode_weekly` | 对象，以周数的字符串为键，如 `"1"`；每周至少两题，每题有 `title` 与 HTTP(S) `url`。 |
| `days` | 长度必须为 `weeks × 7`，每周七天齐全。 |

`daily_hours` 在格式层面允许 0–24，但当前每天的 `planned_minutes` 必须是 **1–1440 的整数**，所以实际可导入的七天时长都至少为 1 分钟。每一天的 `planned_minutes` 必须等于对应 `daily_hours` 按程序 `round(daily_hours × 60)` 换算后的分钟数。需要安排休息日时，可将其设为最短的计划任务，并在标题中注明休息/复盘。

### 每日任务格式

每个 `days[]` 元素都必须包含下列内容：

| 字段 | 格式和要求 |
| --- | --- |
| `id`、`week`、`day` | ID 严格按 `W01D01`、`W01D02` … 编号，并与周、天整数一致；全计划不能重复或缺天。 |
| `title`、`course_section`、`track` | 非空字符串，分别表示任务标题、课程章节和学习方向。 |
| `planned_minutes` | 1–1440 的整数，须与该周相应位置的 `daily_hours` 一致。 |
| `time_budget` | 包含非负整数 `theory_minutes`、`practice_minutes`、`verification_minutes`；三者之和等于 `planned_minutes`。 |
| `course_readings` | 至少一项；每项至少有非空 `title` 和以 `http://` 或 `https://` 开头的 `url`。可补充 `type`、`mandatory`、`estimated_minutes`。 |
| `coding_exercises` | 至少一项；每项有全计划唯一的 `id`、非空 `title` 和 `instructions`、`expected_artifacts` 数组。建议补充 `verification`、`requires_manual_implementation`。 |
| `deliverables` | 至少一个非空交付物条目。 |
| `acceptance_tests` | 至少一项；每项有全计划唯一的 `id`、非空 `assertion` 和布尔值 `evidence_required`。建议补充 `pass_rule`。 |
| `leetcode` | 可选的当日题目数组；每周题目仍需填写在顶层 `leetcode_weekly`。 |

最稳妥的制作流程是复制 [完整示例](examples/sample_plan_v3.json)，保持字段结构，修改 `plan_id`、`plan_name`、`curriculum_version` 和每日内容。如果扩展为多周，给 `weekly_themes` 增加对应主题，在 `leetcode_weekly` 为每周配置至少两题，并为每周增加 7 个正确编号的学习日。最后核对每日分钟、三项时间预算与 `total_planned_hours`。例如 8 周、每天 4 小时的计划，应有 56 个 `days`，总计 224 小时。

### 更新现有计划

- **同一个 `plan_id`**：导入视为更新课程内容，保留该计划的学习记录、证据和计时。同一学习日的 ID，以及练习和验收项的 ID，应尽量保持稳定，便于延续对应进度。
- **新的 `plan_id`**：创建另一份独立计划和数据库，不会继承旧计划的进度。
- **缩短计划**：被移除的学习日从日历隐藏，既有记录仍在数据库中；以后重新导入包含这些日子的版本，可再次看到记录。

导入预览会显示变更数量，请在确认前检查。不要仅为了修改标题而更换 `plan_id`。

## 备份、恢复与本地数据

在“设置与备份”中使用“下载当前计划备份”导出当前计划的课程快照和学习记录。**每个需要保存的计划都要分别导出一次**。备份含个人笔记、证据等内容，请自行妥善保存。

恢复时先切换到对应计划、结束正在运行的计时，然后选择备份并查看记录数预览。确认恢复会替换当前计划的数据；程序会先在该计划的 `backups/` 中自动保存恢复前的数据，并保留最近 5 份。新格式备份中的 `plan_id` 必须匹配当前计划；较早没有 `plan_id` 的备份则要求课程日快照完全匹配。

| 运行方式 | 默认数据位置 |
| --- | --- |
| 已安装的桌面版 | `~/.local/share/studywaypoint/` |
| 直接运行源码的浏览器版 | 项目目录下的 `data/` |

桌面版数据目录可用 `TRACKER_DATA_DIR` 环境变量指定。目录中的 `plan_library.json` 记录计划库与当前计划；内置示例存于 `builtin/`，导入的计划分别存于 `plans/<plan_id 的 SHA-256 前 24 位>/`，其中包含 `curriculum.json` 和 `tracker.sqlite3`。重新导入前的课程 JSON 会保存在对应计划的 `source_versions/`，最多保留 5 份。

## 常见问题

- **导入失败**：检查报错字段、JSON 语法、总天数、时间预算、唯一 ID 和 HTTP(S) 链接。文件需使用 UTF-8 编码；优先从完整示例修改。
- **“今天”没有任务**：检查学习起始日期、时区和当前选择的计划；也可从“课程日历”查看其他日期。
- **不能切换或导入计划**：先结束当前计时。
- **恢复提示计划不匹配**：切换到相应 `plan_id` 的计划；旧备份需先导入对应课程。
- **桌面窗口无法启动**：确认处于 Linux 图形会话，且安装了 `python3-gi`、`gir1.2-gtk-3.0`、`gir1.2-webkit2-4.1`。仅浏览器模式只需 Python 3.11+。
- **升级后看不到进度**：先检查是否选中了原计划，以及 `TRACKER_DATA_DIR` 是否指向原数据目录，再考虑从对应计划的备份恢复。

更多升级说明见 [完整使用指南](USER_GUIDE.md)。

## 开发与验证

### 开发日志

每次新增、修改或删除项目内容时，须在同一批变更中更新 [log.md](log.md)。日志按日期记录变更内容、涉及文件和验证结果；文档、测试、打包脚本的改动也要记录。若尚未运行验证，写明“未运行”及原因。不要在日志中写入个人计划、学习记录或 API 密钥。

`log.md` 记录逐次开发过程；[CHANGELOG.md](CHANGELOG.md) 汇总对用户有影响的版本变化。准备 GitHub 发行文件时，源码包和安装包也应包含开发日志。

在源码根目录运行自动化测试：

```bash
python3 -m unittest discover -s tests -v
```

需要生成 Debian 安装包时运行：

```bash
python3 packaging/build_deb.py
```

打包脚本生成可发布的 `.deb`；发布前请按 [发行说明](docs/release_1.4.0.md) 检查文件清单，确认没有加入个人课程 JSON、数据库、备份、布局偏好或 API 密钥。
